# SportsScrap

A French-language phone app (PWA) that shows the **big sports events** of the month in a calendar,
for a small family (3 people). Tapping an event shows the stakes, the favourites, the outsider (underdog)
and a short summary, all generated by an AI that searches the web.

> **Status: design finished, nothing built yet.** The only code is a throwaway feasibility spike.
> The blocker is finding an AI provider with **web search** that is free (or very cheap).
> See [docs/SPIKE.md](docs/SPIKE.md) for what was tried and [docs/NEXT-STEPS.md](docs/NEXT-STEPS.md) to resume.

## Product in one minute

- **Sports (v1):** Cycling, Athletics, Volley-ball, Table tennis. Big events only (Olympics, Worlds, Euros, Tour de France...), men and women.
- **Calendar:** month view by default, plus week and year (heat-map). Filter by sport. Past events stay visible, greyed out.
- **Event sheet:** stakes, up to 3 favourites, one outsider, French interest, summary (120 words max), TV channel in France, source link, "to verify" badge when confidence is low. All AI content is labelled "AI estimate".
- **Sharing:** a plain URL carrying the view and filters (`?view=month&month=2026-11&sports=volley,cycling`). Public site, no accounts, nothing secret.
- **Language:** everything in French, times in Europe/Paris. Code and data fields are in English.

## Architecture in one minute

No server. Everything is pre-generated:

```
GitHub Actions (cron, 1st of each month, + manual trigger)
   -> AI provider with web search (behind a provider interface)
   -> validated JSON committed as events/YYYY-MM.json
GitHub Pages
   -> static PWA reading those JSON files
```

The AI key only exists in GitHub Actions secrets. Stack: TypeScript, Vite, Preact, a PWA plugin, Vitest.

## Where we are stuck

The whole design depends on an AI that can **search the live web** (event dates months ahead cannot be answered reliably from model memory). Findings so far:

- **Gemini (free key):** the key and models work, but every request using Google Search grounding returns `429 RESOURCE_EXHAUSTED`. Details in [docs/SPIKE.md](docs/SPIKE.md).
- **Mistral:** not tested yet (needs the user's key). Web search is an Agents API connector; availability on the free plan is unconfirmed.
- **Claude API:** works with web search but is billed separately from a Claude subscription (a few cents per monthly run).

## Running the spike

Requires Node 18+. Never commit keys; pass them through the environment.

```powershell
$env:MISTRAL_API_KEY = "..."; node spike/mistral-spike.mjs [YYYY-MM]
$env:GEMINI_API_KEY  = "..."; $env:GEMINI_MODEL = "gemini-3.5-flash"; node spike/gemini-spike.mjs [YYYY-MM]
```

Output goes to `spike/out/` (git-ignored).
